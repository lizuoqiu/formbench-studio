## 按使用过程复核

共同的选型边界、真实外形与问题分类见 [通用硬件设计规则](../hardware-design-policy/SKILL.md)；后台为评审注入对应章节。不要把采购件的模型重建解释为需要重新制造这个商品。

评审是 AI 自动迭代的一环，发现问题后把受影响部件、实际后果、修改方向和复查条件交给设计阶段。用户不承担工程审批或修模。资料缺失应触发补查、换型或有依据的尺寸重建；不要建议让无硬件经验的用户解决设计缺陷。

对轻量 demo 按核心功能是否完整成立评审，不默认追求量产产品的附加功能。区分用户明确要求与生成者自己的实现假设；最新反馈可以撤销旧草稿自行加入的停车架、收纳、额外交付或复杂操作授权。结合修复阶段更新并记录的 requirements 核查，不能用已被撤销的假设要求再加回来。简化不能减少要求的轴数、隐藏内部件、略去必要承载/供电/停止逻辑，或放过已测出的干涉。可选功能、外观润色与实际设计缺陷分别说明。

在检查孔位、接线和碰撞前，先在 intent/form 判断整机是否仍是用户想使用的产品。依据实际外观与内部视图、尺寸、部件用途和操作步骤，检查主体是否清楚、辅助机构是否占据不合理的空间、接口是否好接、日常使用是否变得繁琐。名称含“桌面”“紧凑”不是满足要求的证据；零件较多也不自动等于失败。指出具体的支架、托盘、线仓、供电或操作负担及其影响，必要时要求简化对应子系统，而非继续增加补偿件。用户已有设备、成品附件和待制作主体应可区分，用途说明应能让普通用户理解。

检查是否越过用户指定的产品边界。用户要机械臂，完整的内部驱动、控制、结构及壳体是必要范围；外置电源、手机和使用场景不因此变成定制托盘、停车架、收线器或整套工作站的设计任务。对 AI 自行增加的外围制作项目，要求说明它为何无法由主体设计或成品配套解决，缺少依据时在 intent/form 判 repair。外部成品配套只列采购和连接说明、不画进主体 CAD 是允许的；不能把这种范围克制与缺少主体内部件混淆。隐藏仍实际需要制造的外围结构不能消除这个问题。

需要展示的外置成品可按所选型号直接放置原厂或尺寸模型；这种模型不要求专用托盘、架子和收纳盒。网页/手机/Agent 的 controls.kind=command 是通信指令，只要求真实通信与控制路径，不要求 fixedBodyIndex 或手机 CAD。页面上的点动、停止和初始姿态操作须与关节预览一致；不要把预览的停止/复位当成实机急停、回零或路径规划已经实现。

工作台对有有效 `cadPlan.joints` 的装配显示内建「回到初始姿态」。这个按钮取消当前预览操作，并将每轴恢复到其角度范围内最接近 0° 的位置。它由查看器处理，在 `controls` 和离散事件回放之外。用户要求网页预览复位时，评审核对关节范围与初始姿态，并在实际浏览器从偏离初始角的位置检查按钮。实机回零、断电及重新使能仍按各自的控制和电气证据判断。

允许在保持功能的前提下集成或替换冗余结构，但替代设计必须保留所需承载、供电、防护、走线和运动能力，并重新核查全部受影响关系。隐藏手机或电源参考模型只改变展示，不会解决真实占地或装配问题；不能据此通过工程检查。固定的营销示例、图片或视觉精细度不证明来源尺寸、原厂 CAD、真实联动或可制造性。

装配支持 320 个独立实体、每件最多 80 个特征、展开后累计 4096 个特征。实际安装件须逐一定位，分件可与同一物理实例关联。对上一版使用增量操作，应用操作后的完整 candidate 仍按全量标准检查。已确认的部件、接口及配合可沿用。

额度耗尽导致未完成的查询与模型没有通过状态，也不证明商品或原厂 CAD 不存在。后台保留任务并等待服务恢复；未完成检查不能改写为正面评审。接线、端子与内部通道的容量以当前调用方 schema 和校验器为准；表格容量与电气正确性分别处理，索引、方向和通道证据检查必须保留。

本模块交付数字设计。接线、机构、数据链、控制规则和交互预览须完整且自洽；固件编译包、签名手机应用、刷写和实物测试属于后续实现。评审不得把尚未执行这些后续步骤单独当作本轮失败原因，也不得将设计说明或预览当作它们已经完成的证据。生成者自行承诺的额外交付应纠正，不得扩大为用户必须补做的新任务。

检查草稿是否把尚未完成的必要工程设计转交给制作方。例如，功能必须依赖改板、隔离电源路径或补齐传动，而当前只写“制作方查明后修改”，应判 repair，并明确 AI 还须补查或设计哪一段。制作方按图执行和实物验证可以留作后续步骤；关键工作原理、器件连接和实现方式必须在当前设计中可追踪，不能以验收清单代替。

收到 iso、front、right、top、inside 图像时逐一检查。这些图由本轮实际 CAD 网格与已导入的来源模型渲染；不把某方向遮挡当作零件缺失，也不因外观好看忽略内部无固定、传动断开、外壳互穿和接线缺失。缺少实际图像时不能声称已视觉审阅。几何采样、预览逻辑与实物实验分别说明。通过条件是用户要求在设计中落实且无已知功能矛盾；实物额定性能仍需对应的实测证据。

geometry.status 为 unavailable 表示声明的运动检查未完成；即使 issues 为空，也不能作为完成依据。后台会保留未测原因并阻止发布。not-applicable 仅表示当前设计没有声明实体行程，不能用来取消用户要求的运动。

持续任务会先逐件获取资料、尝试导入原厂文件，随后执行 CAD 编译、几何检查和本轮评审。根据 importedModel 与 catalogGeometry 判断真实加载的模型及其安装锚点；已有整件模型的锚点在浏览器中显示原始几何。零件只有商品链接时，仍检查其尺寸及配合依据。查询或导入失败有具体记录时，允许有依据的尺寸建模，并列出需要实物核实的局部细节。缺少实物试验本身不阻止设计预览，明确的功能矛盾或没有实现的用户要求仍需修订。

catalogGeometry 的 meshPlacements 列出已从同一原厂 CAD 分别绑定的 body、物理实例和网格索引。对照来源网格、装配基准及 movingBodyIndices 复核定件和随动件的归属。浏览器和图片使用所选原厂网格；几何扫掠报告对其 reference box 仍按包络记录。查出必须使用独立网格的位置时，区分确实可分离的子件与源文件中已合并的几何，也核对模型中的附件是否适用于当前安装配置。

catalogGeometry 的 dimensionedBodies 记录同一安装实例中由资料补齐的实体及依据。结合已保存原厂网格、原厂图纸与已编译装配，复核这些实体的轴、配合面、所需留位和固定或随动关系。实际可分离的原厂子件须优先用来源网格，需按资料重建已合并部分时以已注明的估算范围为准。

核对 BOM 的完整订货型号与 evidenceModel、商品页、尺寸和 CAD 的身份是否一致。research.alternatives 是换型候选，不是当前型号的证据；只有 AI 明确修改 BOM 并完成新型号查证与装配后，才能使用其来源。identityStatus=mismatch 仍是待修复的对应关系，不能把不同后缀或相似外形的部件混为一件。

对 cadPlan.joints 检查轴数、父子关系、输出连接、实际固定件和下游实体，轴线及行程与驱动件规格相符。它提供设备的连续转轴预览。外部手机通过已选控制器协议下发运动命令时，核查数据链及供电依据。requiresInteraction 专指还需要 controls/states/transitions 表达的离散交互逻辑；已有 joints 能表达的连续运动按该模型评估。geometry 的逐轴采样不覆盖全部联动姿态、载荷或线束应力，physicalChecks 保存这些后续测试。

以当前用户要求、先前仍有效的约束和本轮实际收到的设计为准。先找出用户应当能够完成的一次操作，按顺序追踪触发前、操作中、操作后和复位后的状态。每个判断都指向具体部件、几何特征、端子、状态规则或测试结果。没有给出某项依据时，说明缺哪一项、它会影响什么判断。

- **机械输入与传动。** 找到手指、物体或执行器首先作用的面，然后沿传力路径找到随动件、固定座和触发点。核对动作方向、转轴或滑动轴、支承、接合面、止挡与复位方式。分别检查初始位置、运动途中和终点的通路，关注安装孔、壳壁、导线与相邻件。声称两件咬合、同轴或压到开关时，引用实际位置、尺寸或数据表。转动加按压共用一个旋钮时，分别检查两种动作，核对旋钮与轴的连接、轴向触发行程和固定端。完全被动的结构沿“施力、运动、到位、保持或释放”检查即可。
- **电气与响应。** 对电子交互，沿感知器件、输入端子、控制器、输出端子、执行器或指示器追踪到用户看到、听到或摸到的变化。核对 BOM 所选型号、共同参考地、电源方向、电压和必要的驱动或限流；缺少具体料号、引脚定义或负载数据时保留待查。用交互模型的 controls、outputs、connections、states、transitions 核对同一条路径，包括必要的定时、边界值与复位。按键事件存在或屏幕数值变化可以证明预览逻辑，仍需查实际开关是否会触发、驱动是否有电和输出是否可感知。
- **整机装配与可见性。** 对需要定位的采购件或打印件，核对同一 BOM 项在装配中对应的几何、固定面和连接位置。切开视图或内部记录应能定位影响操作的电子件，检查端口可达、线束两端及所需净空。指示灯或显示屏还须有与使用方向一致的可见窗口。包络可以支持布局判断；引脚、安装面、螺纹等局部形状需要相应证据。

对接线可视化，分别核对 `connections` 的电气路径和 `terminals` 的物理端点。沿每根线核查两端的 BOM 行、针名、已装实体及局部坐标，并结合 `wiring.coverage`、`bothPositioned`、`bothSupported` 判断剩余不确定性。导线落在接线部件上的焊盘、金属脚或已确认的端子面才能支持对应的几何判断。壳体中心、整块控制板、连接器外轮廓与未知的内部触点应分别说明；只能给出近似落点的线记录为估算。若关键端子有图纸或可见接触特征但端点明显悬空，给出两端名称、错误实体或偏移以及可执行的修正。无资料的商品将具体待测项留给选型或实测。实际导通、焊接强度、线材弯曲半径和运动时的净空仍由各自的证据支持。

区分信号输入与直接切换电源的机械开关；后者应有真实接点、电源通路和活动结构，不要求虚构主控 GPIO。USB 的双向导线与芯片内部有向通道分别检查，内部双向路径需要对应型号资料。用户自备、独立供电的外部 USB Host 无需另画手机内部电池线路；仍须核对 VBUS 方向、共地、数据正负端和系统实际供电。

`systemEvents` 表示来自真实已接线器件的连接、反馈、超时或故障条件，不能要求这些事件具有用户操作的动体。核对检测器件、sourcePins、条件和 timeout 的 delayMs；事件注入回放只能证明所声明状态转换与输出，不能证明实际检测、固件时间或制动延迟。真实通信时序和停止性能仍列入实物验证，不能将未执行的仿真当作通过，也不能让生成者用虚构物理控件替代系统事件。

运动输出可以对应关节明确驱动的负载，执行器固定壳体不必属于运动实体。多台同型号器件共用 BOM 行时，通过端子绑定的独立实体核对每个实例及其连线，不能误当作单芯片内部短接。负角度的旋转增量须结合单位轴方向判断；触屏事件没有实体位移。仍检查实际安装、止挡、信号来源及状态，数据容量扩展不等于这些检查已经通过。

有止挡的旋钮用 controls.range 的绝对角度范围及 initial 核对开关接点；increase/decrease 按实际角度增减触发，越过挡位不能切换电路。持续按压用同一控件的 down/up/cancel 事件，分别检查按下、抬起、移交或取消后的状态。运动输出用 motion.type/index/speed 绑定 CAD 关节或直线行程，forward/reverse 表示沿其单位轴的正反方向；只显示 on 的输出不能被当作已演示有方向的运动。核对使能、单轴选择、方向、释放终止，以及退托/复电/故障恢复条件；动画在关节边界停止不等同于实际控制器限位或制动实测。

## 问题、修复与证据

`geometry.reconstructedParts` 是后台从原始完整锚点实际匹配出的记录，包含部件/实体索引、独立模型原生尺寸、实际插入特征数、单件编译引擎及安装后的基准。总装中这些锚点已经展开为特征，因此不要在展开后的候选中再次要求它仍是一个 box，也不要忽略已确认的安装匹配。结合总装 compilation 及图像检查位置、朝向、让位和功能；匹配成功不证明原厂精度或实物插合，缺失与不匹配项仍须处理。

多轴装配同时查看逐轴和联动几何报告。联动检查使用查看器相同的串联变换，采样同向、交错角度范围端点及其中间组合；单轴分别没有干涉不能替代组合检查。报告给出的关节角、实体索引和相交体积可作为自动修订依据。相同运动组的刚性接触不作相对运动碰撞。包络、可压缩件和曲面离散薄层仍保留不确定性；有限组合采样不是全角度空间、连续路径、载荷或动力学证明。几何检查未完成时仍须继续修复或恢复检测，不能仅凭联动动画宣布通过。

当前查看器只执行已声明的串联关节、每轴角限和交互状态，不执行文中设想的多轴禁入域或轨迹规划。不能以尚未实现的“未来控制器会拒绝”抹去已测实体干涉，也不能把静态柔性材料宣称为已验证的联动变形。实际试验与厂商签认仅作为后续验证，未取得的记录不能伪造为已完成；区分设计证据不足和实物试验尚未执行。

结构字段有效后，机械绑定、电气连通、端子位置和状态逻辑应独立检查并合并问题。一项失败不能隐藏其他类别的结果；修复规划应同时处理这些依据，避免每轮仅消除第一个错误。恢复旧任务时重新运行当前校验，保留原评审记录。

评审或修复计划被输出额度截断时，后台在本阶段保留不完整文字和原始证据，提高额度后再尝试一次。返回完整结构化结论，不能只续写尾部；不完整评审不是通过证据。后端记录恢复前后额度与来源调用的用量，只有完整结果仍通过原有验证后才进入后续阶段。

优先报告会让用户做不了某个动作、得不到承诺的反馈或无法完成装配的具体问题。按调用方的结构化格式，给出受影响的要求与部件、现有证据、实际后果、尽量小的修改及其复查方法。例如，若确认名义槽宽小于穿槽件宽度，引用两者的数值和所在部件；若只知道槽宽，则指出还需要哪项测量才能判断。不要把可选美化、未知的实物结果或缺少与本设计无关的零件列为确定缺陷。

复核修订时对照上轮问题记录，写明改了哪一项、修订后的证据及其结果。检查相关安装、接线、状态规则是否仍满足原要求；变更了说明文字但实体或逻辑没改时，保留该问题。确实需要实物才能判断的事项，给出能区分成功与失败的台架或试配观察。

把用户指定值、图示标注、设计假设、计算或已执行测试、待实测项写清楚。只有收到实际网格、运行轨迹或电测记录才引用相应结果。静态截图、STL 成功导出和预览动画均不能证明通电、载荷、可靠性、触感或实物运作。资料足以说明设计自洽时，可以给出相应结论，并指明尚待怎样的实物验证。
