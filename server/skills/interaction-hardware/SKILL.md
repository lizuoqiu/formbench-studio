## 从交互动作推导硬件

选型、自定义范围、成品外置与模型真实外形遵循 [通用硬件设计规则](../hardware-design-policy/SKILL.md)。后台按当前阶段注入相关章节，工程细节继续使用下述接口约定。

## 持续设计任务与逐件资料

用户不需要审阅工程决策。由 AI 决定并记录尺寸、器件、固定方式、供电、通信和制造工艺，依据检查结果主动修订。涉及用户体验的偏好可以协商，孔位、选型、下载失败和几何错误不能交给用户处理。实物测试的未执行状态与设计中已知的矛盾分开记录。

用户要 demo、轻量化原型或“能用即可”时，先选择能完整演示核心交互的最小方案。把用户明确要求的能力、AI 选择的实现假设、可选扩展分开；优先成熟成品模块和简明的机构、供电与控制链，暂不加入手势库、收纳、展示设施或复杂的操作授权流程。必要支承、基本停止、限位及合理的失联/断电处理仍由设计落实，不以降低核心能力或隐藏缺陷换取简单。更少零件不是硬性通过条件。

首轮 requirements 是 AI 对需求的推导，不是不可变的用户原话。每次修复先与用户原始目标及最新反馈核对，输出更新后的 requirements 并记录原因：保留明确要求，纠正过时假设和自行扩大范围的承诺。回到初始姿态不自动意味着另造停车架；需要单独支撑时给出当前方案的具体工程依据，优先重新选择可满足轻量目标的机构。此后的自动检查和修订使用更新后的要求，不能把旧草稿当作用户已经批准的产品规格。

先确定整机的使用过程、主体范围、合理占地和运动空间，再设计辅助结构。主体、外接电源/附件、用户已有设备分别说明用途；purpose 用普通用户能理解的语句描述它在整机中做什么，不能只写尺寸、材料或“固定 ID4”。用户自备手机等情境参照使用 provided，不当作待打印件。不能为让预览好看而伪造尺寸或隐藏必要机构。

BOM 每行的 `name`、`model`、`spec`、`purpose` 的长度上限分别为 200、240、800、500。新增或修订零件时逐项检查这些字段。长引脚表、供电计算和装配顺序放到相应的接线字段或设计 `steps`，最多 80 个步骤，每步最多 2000 字。增量修复时合并已被替代的步骤，保留支持装配及功能的细节。

默认设计范围就是用户点名的产品主体，不把整个使用环境扩展成制造任务。机械臂的臂段、六轴关节、内部电机/控制板、传动、必要走线和外壳属于主体，须完整设计。外置成品电源、数据线等按需要选购并说明接口；未知成品件先确定型号，需展示时直接按它的原厂 CAD 或尺寸建模，摆在主体外并说明用途，不设计专用托盘、护盒、桌架或收纳器。用户自备手机只说明适用条件，不必建立手机实体。外部成品模型不应遮挡主体或被误标为待打印结构。

AI 自行补出的独立停车架、收线装置等不能因为已有草稿包含它就自动成为需求。优先通过主体的结构、布局和已有器件解决必要功能；确实无法在主体内解决时，先给出工程依据和对使用范围的影响，不能默默扩大项目。取消冗余配套必须保留它承担的必要功能并落实替代方案；不要把内部驱动、支承或必要保护误删成“附属品”。

修订时重新检查整体形态，不只补局部缺陷。若支架、停车托、线仓、护罩等辅助结构累积后压倒主体、占地明显超出产品用途，或使用步骤依赖用户理解复杂工程操作，先比较集成已有功能、简化失败子系统、换用合适模块的方案，再决定是否加件。必要的供电、承载、防护和走线仍要落实。复用正确选型和独立模型，以增量操作替换受影响结构并更新关联引用；不能把“增量”理解成只准添加、不准删去已被新结构取代的冗余件，也不能借简化减少用户要求的自由度或能力。

API 额度耗尽是服务不可用，不是该零件不存在或无法建模的证据。保存当前草稿与已完成资料，停止新的付费尝试；恢复额度后继续同一个任务，不据此删除器件、编造商品链接或用占位形体交付。电气数据支持最多 224 条 connections、448 个 terminals 和 24 条 signalChannels。修改电气网络时在同一个补丁中更新连接和端点，记录实际针脚、物理实例和内部通道的来源。

本模块产出数字设计：完整 BOM、CAD、接线及交互预览。需要软件的设备应确定接口、协议、状态和时序，并写明后续实现步骤；未生成或未构建的固件、手机应用及未执行的刷机、实物试验不得写成已经交付，也不要求用户在当前阶段提供这些结果。数字设计检查仍须消除缺件、错误的电气路径和已知几何干涉。

修复计划中的实物测试、供应商签认图或首件测量仍是未执行的后续验证，不能由网页检索冒充取得。当前设计依据应使用已查到的资料与清楚标注的估算；影响工作原理且无法建立合理依据的部分，主动换用资料充分的方案。不要把计划中新增的实体或软件承诺当成已经实现。

制作方依据已完成的设计加工、接线、组装和测试。影响功能的电路、隔离路径、连接方式及必要结构由 AI 在交付前确定；不能用“由制作方找出电路并改板”“现场补设计”代替缺失方案。必要资料不足时主动补查、选用资料充分的器件或重新设计相关子系统，再接受检查。装配公差、加工差异和需实测的性能保留对应验证步骤。

后端按阶段加载版本固定的 ForgeCAD 官方资料：design-spec 负责目标与工程规格；build-model、joint-design 和 positioning 负责完整实体及装配；reconstruct-from-images 提供证据驱动的重建方法；inspect-model 与 grade-model 负责检查及独立复核。官方原文保存在 forgecad-official，运行时适配在 official-skills.mjs。只使用当前 JSON 契约及编译器能执行的能力，不把文档中出现的新版命令写成执行结果。

导入模型的 geometrySummary 给出实际子件名称、数量和在整件包络中心坐标系下的边界，originalOriginMm 表示原 CAD 原点在该坐标系的位置。先用这些信息理解模型已含的舵盘、从动端、连接器及固定件，再结合机械图确定轴线与配合；名称或边界本身不证明精确孔位。不要把已包含在完整原厂 CAD 中的附件再叠放一遍；调整初始 BOM 的包含关系和装配表达，保留实际采购数量。

工作顺序：规划 → 逐件研究和下载 → 单件建模并实际编译 → 整机装配和实际编译 → 多视角与几何/功能检查 → 制定修复计划 → 有针对性地补查、修改、重新检查。三个设计回合是后台的一次执行时段，不是质量截止条件；仍有设计缺陷时自动进入下一时段。反复出现的缺陷需要重新规划失败子系统，保持用户的功能要求，不通过删除零件、减少轴数或降低要求换取通过。

单件重试保留上次未验证的几何草稿及具体错误，基于已有工作修正或补全；草稿被截断不代表其中所有参数都错，也不代表任何部分已通过。遇到输出额度不足，后台提高该件的预算并在恢复后保留。只有新一轮返回完整数据、通过结构检查和实际编译后，才保存为可装配的独立模型。

整机输出同样保留被截断的草稿和失败原因，自动提高输出额度后从原修复方案继续，返回完整且索引一致的数据。截断不构成已完成一轮设计或通过检查，不能以删掉所需部件来压缩结果。

所有已有设计的修订一律使用 hardware_design_revision，包括小项目、用户调整以及评审后的自动修复；只有没有已有设计的首轮才输出整份设计。模型返回 JSON Pointer 增量操作，后台在本轮 rejectedDraft 的副本上应用。先确定受影响的零件、安装关系和关联控制，再仅修改这些字段；保留其余型号、尺寸、资料、几何和索引。新增实体优先追加；改动或删除数组项时同步修改全部相关引用。只有整个子系统确实受影响时才替换该子系统，并在 summary 说明理由，后台禁止整体写入或删除 /parts、/cadPlan、/cadPlan/bodies，必须定位到具体零件、实体或字段，不能用大替换冒充增量。

逐件资料以 selectedParts/updatedParts 中的 research 为当前依据。后台发送同型号的当前来源记录时，省去由它生成的重复界面资料副本；型号、数量、尺寸、独立模型基准、估算和原厂模型组成仍保留。请求去重不修改已保存的 BOM、CAD 或原始证据，不用缩短上下文代替完整检查。

后台复用未变化部件的已存资料及独立模型，对新增或变更部件查证和建模，再编译完整装配并重新进行几何、电气、交互和功能评审。修订范围小不缩小检查范围。操作无效时修正同一基线的操作，不丢弃旧版、不退回全量重写；输出被截断时保留未应用操作和错误，恢复时返回完整操作列表。操作记录和每轮完整结果都留存，不能把“补丁已应用”当作检查通过。每个实际安装的同型号件独立定位；不要为压缩输出把多颗螺钉合成一个锚点或将安装件改成清单附件。

定向补查后需要修订已编译单件时，把旧模型及修订原因一同交给建模步骤，按新依据调整受影响的特征和基准，保留仍正确的部分。旧模型的编译成功不代表新配合已经通过；新模型仍须重新编译后才用于装配。

编译后的单件记录所用资料查询版本与修订问题。恢复任务时，若该模型已经使用同一版资料完成同一个修订问题，直接复用，不再次发起建模；资料或问题改变时才重新排入修订。没有来源版本记录的旧模型仍需在相应补查后核对，不能靠补写通过标记来冒充已更新。

下载原厂 CAD 失败后继续查机械图、数据表、可用直链及安装基准，建立独立的参数模型。research.reconstruction 是已用 ForgeCAD 编译的零件模型，包含 sizeMm、datums 和 assumptions。用该 sizeMm 的单个完整 reference box 锚点定位每个实际实例；后台在整机编译前展开其独立特征。此处的 box 是安装记录，最终展示模型必须是展开后的几何。没有实际输入的照片不能声称按照片重建。原厂和已匹配的目录模型优先复用。

装配草稿新增或换型后，后台会再次逐件查询和建模。若新模型与原先估计不同，将采购/随附整件的 BOM 尺寸和全部安装锚点更新为新模型原生尺寸，依据新基准重新定位相邻接口；不能只更新资料卡而继续用旧形体。需要拆分固定与活动子件的采购总成应明确各子件的几何及运动归属；裁切原料按实际用量和成形后的尺寸表达。

后台在新增/换型后的资料阶段自动比较整机安装锚点与已编译单件的尺寸、数量和基准；不一致即交给 AI 做装配增量修订，再核对受影响部件，每轮最多两次局部对齐。仍未解决的问题进入完整评审和下一轮修复，不标记为通过，也不等待用户指出。装配操作、前后版本与检查结果均保存；文件容量或计算时限不足是执行预算问题，应恢复完整检测，不能靠删必要实体规避。

先做完整的闭合产品及内部件，再用查看器隐藏外壳检查内部；不能把永久切开的外壳当作产品。安装件数量应与实际实例对应。外壳需有真实容纳空间、接口开口和固定方式。多视角评审使用实际编译实体和已读取的来源模型，不能用生成图片替代 CAD 检查。

正常生成先规划 requirements 和完整选型，后端逐件查询商品、原厂机械资料及 CAD，实际下载和读取文件，再把 selectedParts 或 updatedParts 交给设计阶段。所有型号和来源由当前任务取得。保留用户目标与已满足的要求，按生成、实际建模、检查、修订的顺序推进。后端保存每轮候选、检查和来源，可从中断处继续。

每件购买品保留完整厂名、型号、供货版本和数量。沿用已查部件时逐字保留 selectedParts/updatedParts 中的 model，以便关联既有资料。每项 kind 写 purchase（购买）、custom（自制）、material（材料）、included（主件附带）或 provided（用户已有）。用户要求连接自己的手机等现有设备时，可列 provided 并说明接口要求及实机待核对处，无需为它寻找购买链接；不能把尚需购买的器件转成 provided 来绕过采购检查。来源查询覆盖安装件、线材和耗材；不同商品或加工原料分别列项，不用“按图配料的物料包”代替实际选型。自制件说明材料、加工方法与配合对象，主机已含子件写明包含关系。结构变更需要新型号时正常更新 BOM，后端会为新型号重新查询；在拿到资料后重新核对关联的结构。不能把上一型号的文件和尺寸沿用到新型号。

research.productUrl 是搜索实际找到的商品路径，productStatus 说明后端是否取得页面。research.sourceUrl、sourceQuote、detail 是该型号的尺寸、接口和其他资料。extentMm 只有原厂明确的整件三轴尺寸才填写。importedModel 表示服务器已下载并解析该件 CAD，sizeMm 是解析出来的原生毫米轴向，后端保留源文件及网格。cadSearch/cadError 说明搜寻与解析的具体结果，只有链接的资料不能称已导入。

逐件查询返回明确的 evidenceModel；商品、尺寸和 CAD 必须属于同一个完整订货型号。替代型号保存在 research.alternatives，不能借原 BOM 行的名字展示或重建替代品。设计阶段选择替代品时，以增量操作明确更新 model 与相关规格，后台随后按新型号查证、建模并对齐安装。identityStatus=mismatch 的记录尚未关联到选型，不作当前部件的建模依据；用户无需负责辨别型号。旧版定向查询缺少身份记录时，由后台重新查证后再使用。

已导入模型可用一个 role=reference、仅含单个 add box 的 body 定位每个实际安装实例。box.sizeMm 精确采用 importedModel.sizeMm，box.centerMm 和 rotationDeg 确定其位置与朝向。查看器和导出包以原始毫米网格替换锚点。每件不同采购物另列 BOM。原厂模型只有部分结构时，选用完整文件或按照有出处的尺寸补充实体，并说明估算。

同一原厂 CAD 中已有独立的定件与随动网格时，直接复用 `importedModel.geometrySummary.meshes` 所列零基索引和包围盒。固定和随动子件分别用 body 定位，在各 body 填 `sourceMeshes: {instanceIndex, meshIndices}`。instanceIndex 从 0 到 BOM 数量减 1，同一实例中的同一网格只能使用一次。每个 body 用一个 reference add box，三轴 sizeMm 为所选原生网格联合包围盒的长度，centerMm 为该子件包围盒中心的安装位置，rotationDeg 保留正确朝向。查看器和 CAD 导出按 body 分开读取原始网格。本行既已分件定位，就不要再放同一行的整件锚点；如果文件包含不同配置的闲置子件，在 spec 写明实例对应的配置及省略依据。没有选择网格时可省略 sourceMeshes 或填 null。合并在同一网格的壳体和运动件无法通过选择索引拆开；使用可实际分离的原厂文件，或按有出处的尺寸补充可辨认的结构和让位。

若已保存的原厂文件只把受影响的几个子件合并在一起，可在同一安装实例中复用可分离的原厂子件，仅用有出处的尺寸补齐合并部分。补齐的 body 使用正常可编译的 features，在 sourceMeshes 填同一个 instanceIndex、空 meshIndices 和 dimensionBasis。依据须写明原文件未能分离的几何、所采用的已查基准以及省略范围。每个这样安装的实例仍须至少使用一个实际原厂分件。把替代几何摆成有功能的独立实体，按实际运动归属绑定。

每轮读取 definitionIssues、geometry、catalogGeometry、behavior 及独立评审。针对部件索引和具体问题修改几何、接口或交互定义，并复查受影响的连接。相同问题再次出现时先确认是否缺少资料、模型表达不当或机构确有矛盾，调整失败的选择和结构。成功编译与预览评审只记录已执行的检查，实物承载、供电能力和加工公差仍按资料与实测分别说明。

## 串联旋转机构

cadPlan.joints 表示设备驱动的转轴，按从基座到末端的顺序定义，最多 12 轴。每项填写 name、axis（归一化）、pivotMm（零位的装配世界坐标）、minDegrees、maxDegrees（包含零位）、movingBodyIndices（本轴带动的全部下游实体）、fixedBodyIndex（本轴定件）、actuatorPartIndex（驱动件 BOM 索引）、parentIndex（上级关节在 joints 中的索引，根关节 null）。父轴带动子轴的固定件以及全部下游动件。轴线必须对应执行器输出及实际连接，固定壳体与旋转输出结构分别表达。

查看器提供逐轴角度操作，ForgeCAD 导出同样的串联关节。专用装置上的控制器负责驱动关节，通过 joints 表示机械运动。在部件资料与 steps 中写明设备侧的数据接口、驱动电压、共同参考地、协议和固件要求。用户操作有明确的输入、状态转换及反馈时，再使用 interaction 状态模型。上电常亮的无状态电路可将 interaction 设为 null，并完整说明电源和限流路径。使用 Type-C 接口时，核实设备角色、实际协议和电机供电预算。

当前 joints 支持父子刚体变换及每轴 minDegrees/maxDegrees，不支持仅在文字中声明的多轴禁入域、碰撞规划器或非线性柔性件驱动。必须消除已声明可操作范围内检测到的实际结构穿透；不能写“未来固件会拒绝这个姿态”就把仍可拖动到碰撞处的预览当作通过。反复碰撞时重新规划失败结构，保持用户要求的轴数、功能与有效运动。软线和耗材可以按其实际证据表达，不能声称静态卷带已实现联动变形；软件状态事件也不能代替未实现的几何约束。

从使用者接近的方向出发，明确是谁先动、设备要做什么、用户在哪里接触它、怎样检测接触、怎样结束和复位。在简介里用自然语言写出这个动作顺序。用户希望 AI 与自己互相回应、递来物体或主动接触时，让装置执行属于它的那个动作。例如，桌面 AI 与人碰拳时，可先缓慢向人伸出柔软接触面、停下等人轻碰，再收回；如果用户明确只想碰一个静止的感应面并得到振动反馈，就保持静止。被动按压、感知和振动可以独立使用。不要用震动冒充用户要求的主动行程。

把主动动作落实到可采购、可安装的执行器、驱动/控制器、传动或导向件、随动件、固定支撑和接口。简洁的成品直线模组可集成执行器、传动和导向。根据所选方案给出控制信号、供电和动作结束条件；把未经验证的行程与额定参数标为设计目标或待查。面向手部轻触的机构应低速接近并停下等人接触，避免夹点，考虑检测接触后停止和回退。不把概念预览当作真实电气或人体试验。

电子交互应能从真实输入端子追踪到控制器，再从控制器追到反馈器件。用 connections 记录跨器件的实际导线，包括信号、供电、共地、上拉或输出使能所需的接线。经过缓冲器、电平转换器或驱动器时，将上游输出接至中间器件输入，再将该器件的输出接向下游；检查各侧电源、逻辑阈值、使能的有效电平和上电状态。若信号从两个器件实际直连，应说明所选规格允许直连的依据。对于由精确型号资料证明的有向内部通路，可用 signalChannels 记 partIndex、model、inputPin、outputPin、sourceUrl、evidence，例如同一已选缓冲器的一个数据输入与对应输出。芯片内部通道和跨器件导线分别表达。资料未证实时，保留待查的通道，或选用有依据的器件；不能虚构穿过芯片的直连导线来闭合模型。

遇到原装带屏、按键、触控面或时钟的成品主控，先读 research.factoryInterfaces（修订时也在该件 sourcing.factoryInterfaces）。它们是逐件查证已从该型号资料读出的功能，引用格式为 builtin:<id>。在同一主控上，触控或按键的 signalPins 只放一个这样的引用；多个屏幕按钮可共用同一 touch。显示、灯或声音输出的 signalPin 可引用同类功能，超时事件的 sourcePins 可引用 clock。保留主控及屏的实际 CAD 位置，无需替这些已装好的功能新建采购件、引线、terminals 或 signalChannels。没有已核实的对应 id 时请求具体资料或更换有依据的方案。外接传感器数据、USB 命令、电机控制、电源和地始终用实物针脚；不得用内置时钟冒充传感读数。

真正的半双工或双向信号导体在 connections 中只列一次，并将该条的 bidirectional 设为 true。供电、共地、单向信号填 false。每个双向开关仍须按数据表明确正反两个内部 signalChannels 的脚位和来源，并核对两侧实际接线、选通信号、掉电隔离和默认状态。

给使用者看的 name 用简短的硬件名称，如“桌面提醒灯”。用户指定的名称照用。summary 用一到三句说清什么时候触发、哪个部件会做什么，以及用户能看到或感到什么。只在帮助理解时带上本方案已有的行程、材料或供电方式。运动控件用“部件 + 动作”作标签，如“滑台伸缩”。正文用日常中文，省去产品昵称、广告语和装置内心独白。把选型依据、尺寸假设、装配注意事项和具体的实物检查放到零件详情或 steps。用户在操作时必须知道的事项仍写在相关动作旁。

直接切换电源的机械开关可以作为操作输入：在 signalPins 中列其实际接通/断开使用的电源触点，并用 power 接线记录上游输入和下游输出，不为此虚构 GPIO。转动、按压或滑动输入仍须有独立活动几何、固定基座及有效行程，不能让整件定位盒代替旋钮运动。普通传感或按键信号仍须追踪到真实主控输入。

## 让操作触发可观察的状态变化

当用户从已有手机或电脑通过本地网络使用设备，设备提供的网页使用 outputs.kind="web"，partIndex 为安装在装置内的主控，signalPin 引用该型号查证过的 builtin:<wifi 功能 id>，bodyIndices=[]、motion=null。网页按键用 kind="command"，partIndex 为该主控，signalPins 使用同一个无线接口引用，其余机械字段为空或零。网页连接/断开事件可用该无线接口，网页可发起校时、标定和启停。用专用硬件的传感事件表示标定或运行时的实际取样。说明网页如何建立连接、记录如何保存及再次访问；不为浏览器另买显示屏，不给无线通路画导线。

有线调试台对专用装置发出的按钮指令用 controls.kind="command"，不虚构实体触屏或机械按钮。partIndex 指清单中的外部命令主机（role=external、placement=loose）；fixedBodyIndex=null、movingBodyIndices=[]、axis=[]、pivotMm=[]、step=0、range=null。signalPins 列真实通信总线端子并连接到实际控制器输入，各命令可共享 USB 数据对，由唯一 id/协议消息区分。网页在模型下方显示这些按钮，通过同一交互模型驱动 CAD；纯连续关节预览已有逐轴滑杆、±5°点动、停止当前按住操作和回到初始姿态。不要为这些网页操作额外制造实体按钮。实机回零轨迹和硬件通信需要分别验证。

每条 transitions 记录写入 from、event、to、effect。用户操作的 event 精确引用一个已定义的控件 id。同一状态遇到同一事件只能有一个结果。各状态指定所有输出在该时刻的模式，例如普通开关让灯从 off 变为 on，只用 effect 为 none，timer 取 null，两个状态的 clock 都取 hold。

连接变化、反馈、通信超时与故障用 `systemEvents`，不要虚构滑动手机或用户按钮。每项给出唯一 id、label、kind（connection/timeout/fault/feedback）、检测器件 partIndex、该器件真实已接线的 sourcePins、明确的检测条件 condition。timeout 填正的 delayMs，其余 delayMs 为 null；最多 24 项。transitions.event 引用该 id，effect 为 none，描述事件发生后的响应。与 controls、outputs 以及 timer.expired 不得重名。没有此类事件时给空数组。后台以显式事件注入回放状态转换，网页提供“模拟设备事件”；它不模拟 USB 包、真实固件时钟、制动力学或实测停机延迟。时间阈值和检测实现写入设计，不能把事件注入当作已实测满足阈值。

显示器的 on/off 表示预览中的亮灭；仅有倒计时 timer 时才可用 value/remaining 显示时间。若用户要求先记录、稍后回看，在 interaction.recorder 给出 displayId（实体显示或通过主控无线接口提供的 web 输出）、captureStates、reviewStates（互不重叠，回看时该输出 on）和 sampleEvents（有真实信号来源的 feedback 事件）。从记录状态应能结束并回看；记录时间随经过时长推进，回看保留此次记录，下一次开始才清空。无实体按钮的自动设备允许 controls=[]；开始、查看等必须有可到达的实际事件。没有反馈不等于观测到某种状态，需要明确的有效传感输入才能给它贴标签。预览只支持事件时间记录，不能用它冒充连续波形、定量遥测或已实现固件。其他设备 recorder 填 null。

当前交互容量：最多 32 个用户控件、16 个输出、64 个状态、24 个系统事件和 512 条状态转换。turn 的 step 是带方向的非零角度增量（绝对值不超过 360°）；press/slide 的行程仍为正毫米数。touch 没有位移，movingBodyIndices 必须为空，通用 step 字段不用于运动，生成时写 0。

旋转输入的 `range` 填绝对角度 `{min,max,initial}`，范围在 −360° 至 +360° 内；无机械挡位的连续编码器及非旋转控件填 null。有挡位的开关用 `控件id.increase` / `控件id.decrease` 分别表达实际角度增减时的接点变化；这里的方向指角度变化，和 step 的正负分开。达到挡位后继续向外拖动不产生事件。不能用同一个无方向切换事件把越挡动作当成合闸或断电。

持续按住的按钮或触屏控件用 `控件id.down`、`控件id.up`、`控件id.cancel` 表示按下、抬起、取消。由同一个控件的释放/取消退出运动态，不另造“松开”按钮；正反向分别进入能区分方向的状态。普通单击仍可直接引用控件 id。派生事件名不能再用作独立控件、输出或系统事件 id。

运动输出的 `motion` 明确绑定 `{type:"joint"|"linear",index,speed}`：index 指 cadPlan.joints 或 cadPlan.motions 的索引；speed 是正的预览速度，分别为度/秒或毫米/秒。该输出的 partIndex、bodyIndices、信号端子必须对应被绑定轴的真实执行器实例和负载。每轴使用一个输出，在各状态的 mode 中用 `forward` / `reverse` 表示沿轴的正/负方向，off 停止；on 只表示启用状态，不表示运动方向。非运动输出或仅逻辑显示的运动输出填 motion=null，不能声称它已表现方向运动。按住造成运动的状态必须有原控件的 up/cancel 转移至停止运动的状态。预览使用同一套关节/行程几何并在边界停止；它不模拟扭矩、制动时间或固件反馈。安全退托和重新开放轴的条件用有实际检测来源的 systemEvents 及状态约束表达。

motion 输出的 partIndex 指实际执行器，bodyIndices 可以是 cadPlan.joints/motions 明确由它驱动的负载，不要为通过绑定检查让固定电机外壳一起运动。同一 BOM 行数量大于 1 时，以 terminals 把每个实例的具名针脚绑定到独立实体；转动输出信号的端子实体要与该关节 fixedBodyIndex 一致。实例之间的线是外部导线，同一实例内部跨针通路仍需要资料依据。USB TP_DP/TP_DM 这类测试点保留双向性和正负端身份；器件的 USB 能力可以来自已保存的对应型号资料，不能仅凭任意针脚名称推断。

有倒计时时，从 clock 为 hold 的状态开始。每个 clock 为 run 的状态都要有且仅有一条自然到时转换：event 精确写 `timer.expired`，目标状态的 clock 为 hold，effect 为 none。这个唯一保留事件由时钟产生，不能用作控件或输出 id。不要写 timeout 等别名；若已有一个控件 id 恰为 timeout，它仍表示那个用户操作。

- `none` 表示只切换状态与相应输出，保留设定时长和剩余时长。暂停用 run → hold，继续用 hold → run 并保留暂停时尚余的时间。自然到时的剩余时长为零，重新启动前须重新装入时长。
- `adjust` 仅用于有计时器时的旋转输入，起止状态的 clock 都是 hold。按旋转格数乘以 stepSeconds 调整设定时长，限制在 minSeconds 到 maxSeconds 内，并把剩余时长同步为新设定值。
- `restart` 仅用于有计时器的方案。把剩余时长重新设为当前设定时长，再进入 clock 为 run 的状态。每套倒计时至少有一次这种启动操作。
- `reset` 仅用于有计时器的方案。把剩余时长恢复为当前设定值，进入 clock 为 hold 的状态，等候下一次操作。

例如，旋转控件 wheel 调时，按压控件 push 启动、暂停和恢复。idle、paused 和 done 的 clock 均为 hold，running 为 run。running 显示剩余时间，done 给出完成提示。下面是这台设备的 transitions。

```json
[
  {"from":"idle","event":"wheel","to":"idle","effect":"adjust"},
  {"from":"idle","event":"push","to":"running","effect":"restart"},
  {"from":"running","event":"push","to":"paused","effect":"none"},
  {"from":"paused","event":"push","to":"running","effect":"none"},
  {"from":"running","event":"timer.expired","to":"done","effect":"none"},
  {"from":"done","event":"push","to":"idle","effect":"reset"}
]
```

## 从型号资料确定采购件几何

套件内需要独立安装的内件，标为 included 并说明属于哪个采购项；仍查询该内件本身的机械资料、安装基准和 CAD。单卖商品页可以留空，保留套件包含关系。整套模型已含的部件按其实际组成处理，避免将整套 CAD 放进内件的安装位。恢复中断的任务时沿用最新草稿 BOM，保留已完成的来源及模型。

先确定买到的是哪一个实物，核对厂家、完整料号、版本，以及排针、端子、螺母、摄像头或扩展板是否随货。多个商家共用的系列名只能确定系列。裸芯片、载板、封装库和整套模组分别计量。用户已指定型号时保留该型号。需要另选型号时，交代哪个接口、尺寸或功能要求促成这项变化。

按对实际选购件的适用性使用下列资料；同一件的不同尺寸可以有不同依据。

1. **同型号原厂 CAD。** 已读入对应的几何时，依其原点、坐标轴和安装面定位。资料只提供下载地址时，保留原厂链接，把当前展示的模型按其真实来源说明。已知目录里的按尺寸自绘参考也保留这个身份。
2. **原厂机械图、数据表和明确给出的实测尺寸。** 分别记录 PCB 轮廓、含突出插口/端子的整件包络和孔、轴或安装面的位置。裸板长宽不能直接当作含端子和排针的长宽高；单轴或局部特征的证据只支持对应的量。设计净空、插拔空间、线缆弯曲半径单列，不能加进原厂尺寸。
3. **有尺度的图像资料。** 只有输入确实提供了可量取的图像信息才可使用。需知道同一平面内的标尺或已确认的特征尺寸、观察方向和被测边界。可见面的估计只用于形状、位置或包络近似；透视遮挡、背面和厚度保留未知。不从单张斜视照片确定安装孔距或承力配合。
4. **估算包络。** 可获得的证据不足时使用 estimated。说明包含哪些外露件、哪个尺度影响此次装配、取得哪张图或哪项实测即可替换估计。没有厂家货号的系列件可留作采购候选，在型号落实前将相关开孔或固定尺寸列作试配项。

以当前请求实际附上的目录及厂商机械资料、用户文字测量和既有项目记录为限。后端筛出的带出处机械事实可用于设计；区分只提供链接、已读参数、实际加载的几何和用户指定值。文字提及照片、网址或 STEP 文件时，不能声称已经读图、实测或下载。未取得新来源时标明估计。用户给出的外壳大小属于设计约束，与采购件实测值分开。

## 零件、接口与内部装配

先定交互表面、外部接口与关键器件的安装方向，再定壳体和开口。从使用者的接近方向构思主要剪影：看得到接触面的弧度、长短变化、局部转折和支撑端收拢的过渡。用户指定有辨识度的外形时，按该形体的组成和朝向塑造连续表面，突出有助辨认的轮廓，把承托和电子器件藏到合适位置。打印件各自独立建 body，内腔、连接孔和伸出开口用切除特征表达。

对影响动作、净空、接线或反馈的硬件逐件安排位置，特别是驱动、导向、控制板和接触传感器；不同购买件分别引用 BOM 中真实对应的行号。在内部或切开视图中，应能看到实际位置上的执行器及运动输出、导向、控制板和接触检测件。执行器固定本体与活动推杆是同一采购件的不同 body 时可共享 partIndex。若一件已含导轨或控制板，在 spec/用途写清集成关系，无需重复采购。规格未知时可以估计尺寸与安装位，明确其依据；同型号的已知目录 CAD 优先。软线、耗材可以留在清单，标明不单独定位。

把来源和装配位置作为两个独立问题处理。自制可打印件的实体用 printed，采购件的装配参考用 reference，不用打印采购件的替代物。购买的散料也可能要定位，例如裁切后固定在夹脚上的防滑垫；写明购买单位、用量、裁切尺寸和安装面，避免把一条原料和由它裁成的两块垫重复采购。线材两端若承担穿壳、感知或固定作用，定位关键端点并留出走线空间。无需单独空间定位的用料才列为 loose。预先整合的面板表也可以作为一个总成采购，分别交代面框、开孔、卡耳、背部端子或外置探头的安装需求。

对照 BOM 和内部视图逐件核对安装关系。对于控制、感知、驱动和供电部件，交代器件靠在哪个安装面、工作面或插口朝向哪里、装线和运动需要什么空间。把固定驱动壳、随动输出端和它们连接的零件放在相应位置。安装孔、孔距、轴径和接口偏移使用具体型号的图纸或用户给定尺寸；资料缺失时将其列为待复核，保留合理净空，避免把拍脑袋的孔阵列或焊盘留作开孔模板。

用户给出的采购型号和版本优先。多款器件都满足交互、供电和尺寸要求时，优先选有可追溯机械资料的具体型号。有匹配目录的已安装单体，每一个真实安装实例用一个完整 reference body 作锚点。features 只放一个 add box，sizeMm 按目录原轴 XYZ 顺序填写整件外廓，centerMm 是包络中心，用 rotationDeg 表示整件转向，再用 positionMm 安排整机位置；不交换长宽来模拟旋转。查看器会将有来源的整件参考几何放到这个位置，Forge 程序保留可编辑锚点。板载插座、芯片和按键已经属于该模块，不能另购或再放一遍。重复购买同型号时，每个实际安装实例占用自己的位置；备件留在清单。购买的一个总成若有固定壳和独立运动的轴杆，分别作为同一 partIndex 的不同 reference body，这种情况使用分件几何，不能在每个 body 上再放整个总成。

例如，BOM 选择 Seeed Studio XIAO ESP32S3 基础版（SKU 113991114），且安装配置与本轮目录一致时，使用 xiao-esp32s3 参考。该目录的含 USB 整板包络是 22.482 × 17.78 × 4.46 mm，原始 +X 指向 USB 插入端的外侧，+Z 指向元件面。PCB 单独外廓是 20.955 × 17.78 × 1.25 mm。以含 USB 的包络作模型锚点，以板边与插座基准定位安装支撑和壳体开口。加焊排针或增加扩展板会改变所占空间；C3、带摄像头的 Sense 和未确定版本需各自核对。

未匹配目录时，按选定规格描述能支持的几何。板类从 PCB 厚度和已知连接器轮廓体现插入方向，电机或直线驱动分别表现壳体、输出轴或活动端，导向件表现轨道及滑座，传感器保留实际需要面向外界的探测面。只画该采购件本身具备的特征，按真实相对位置组合，保持名义外廓与 sizeMm 对应。对完全未知的封闭模块，可保留单一尺寸包络，在步骤里注明待取得的型号或图纸；不为增加细节虚构引脚、安装耳、螺孔、内部齿轮或额外 BOM。显示上的估算特征和额定安装尺寸须分清。

板载 USB 等穿壳接口要分别定位插座、PCB 和壳壁。先从板件基准取得插座口中心、插拔方向、插座相对板边的伸出量，并用同一装配变换计算板体和插座的最终位置。按插座前端在壁面上的投影设置贯穿外壁的开口，同时检查插头从壳外完全插入时，插头外被与壳壁之间的净空。按 PCB 实际外形、背面元件高度、插座尾端及安装方向检查内部腔位和支柱。若板边或元件撞壁，可后移整板、缩短局部壁厚或在内壁设置独立让位槽，再复算插入深度。把开口和板体让位分别反映到 CAD；尺寸缺失时列出需要从原厂图纸或实物复核的量。

## 已接针脚在 CAD 中的位置

由 USB 数据链路传来的不同触控或指令，可以共享真实的 D+/D− 数据对；用各自唯一的控件 id 和协议消息区分事件，不为每个屏幕按钮虚构单独电气针脚。保留完整的 USB 连接、主从角色和命令/反馈协议。网页事件重放只验证所声明的交互，不能当作已部署的手机应用或实际固件。

相同极性的 USB 数据端跨器件连接是双向导线，不重复画“回传线”。经过模拟开关等芯片的双向路径仍需按原厂资料声明两个方向的 signalChannels，evidence 写清 inputPin 和 outputPin 的原始针名；有向缓冲器不会因此成为双向器件。用户提供、在机外使用且从 VBUS 供电给接口的 USB Host 可以显示读回数据，不为手机虚构外部电池接线。USB 命令类 controls 的信号脚列实际 D+/D−；VBUS 电源及存在检测另在接线和检测器件中定义，不把 VBUS 当作 USB 数据脚。

根据 `interaction.connections` 的两端建立 `interaction.terminals`。每个实际接线的 BOM 行与针名组合只写一行，多线共用同一针脚时共享端点。按 CAD 实体的局部毫米坐标写 `positionMm`，安装平移由工作台叠加。对自制载板、焊盘、金属脚和端子台，用对应的导电接触特征和实体索引定位，导线终点应接触表面。材料、针序与极性不清楚时写明待核对处。

- `geometry` 表示所建实体上可定位的端子。填写该 BOM 的 `bodyIndex`、零基 `featureIndex` 及具体接触点。可确定型号、朝向与实际焊盘的目录件由工作台匹配。整机原点、板中心或螺丝孔无法单独确定电气针脚。
- `datasheet` 需要对应型号的厂家尺寸图、针脚编号、定位基准和可追溯的 HTTPS `sourceUrl`。只有板框、有针序但未确定朝向，或只能估出焊点区域时选 `estimated`，在 `evidence` 里说明假设。
- `unknown` 表示尚不能定位该点。`positionMm` 和 `featureIndex` 填 null，未确定实体时 `bodyIndex` 也填 null；没有来源链接时 `sourceUrl` 填空字符串。经 USB 插头供电等场合可注明可见的连接器配合面，以及内部哪一触点仍未确定。一次电子逻辑检查或路径可视化不能提供线束成品的导通实测记录。

更换型号、翻板、重新放置或重建特征后，逐条重新核对上述局部坐标、针序和引脚所附实体。端子信息独立于固件状态及计时逻辑。

## 修订既有方案

以最新明确要求更新相关部件，同时沿用仍适用的采购料号、资料依据、已确认尺寸、安装基准、接口朝向、触发方式和行程条件。若换了板卡版本、带排针形式、接口位置或受力方式，重新检查它影响的孔位、支承、走线与相邻件。原版本的尺寸或来源仅在同一实物、同一量法下沿用。把需要重测的量留为待确认；检查计划、CAD 布尔成功或预览能动表示不同阶段，均不能作为实物已装配、额定性能或人体接触试验的结论。

## 工作台几何约定

返回 cadPlan.version 为 1，bodies 包含命名实体。每个 partIndex 对应 BOM parts 的零起始索引，role 为 printed 或 reference。positionMm 表示零件在装配体中的平移。features 使用局部毫米坐标，sizeMm 表示全长，centerMm 表示局部中心。Z 向上。rotationDeg 为绕图元中心依次按 X、Y、Z 轴旋转的三个角度，范围 ±360°；未旋转时给 [0,0,0]。先旋转，再平移至局部中心，再加装配平移。使用 box、ellipsoid 或 cylinder（XY 等径）；按顺序用 add 合并和 cut 减料，从 add 开始。打算形成一体的相邻特征要有体积重叠。BOM 最多 132 行；最多 320 个 body，每件最多 80 个 feature，累计最多 4096（包括独立重建模型展开后的特征）；全长各轴为 0.1–2000 mm，各位置轴范围 ±2000 mm。按 JSON 契约输出，不生成可执行代码。

需要看得清的挡位或指示线时，用实际有厚度的嵌件或涂层实体表达。自制实体可在 body 上填 color 为 #RRGGBB。让字、针与承载件在使用方向有足够颜色对比，并分别绑定实际的定侧和随动侧。注明标记的安装或涂装方式，未指定颜色填 null。

圆角矩形支架、壳壁和开口可用 roundedPrism，四个竖边在 XY 平面倒圆，圆角半径为 min(X,Y) 的 20%。柔软手指、弧端推杆和接触垫可用 capsule，在尺寸最长的轴上有直段，两端是椭圆端帽。按形体选择这些原语并相互组合。将每个需要固定或随动的单独采购件或打印件标为 placement=mounted，并至少放置一个引用其 BOM 索引的 body。无需独立空间定位的松散线材、耗材和附件才标为 loose。

## 直线运动

将设备驱动的旋转轴记为 powered-rotary，在 cadPlan.joints 中表达；主动直线轴记为 powered-linear，同时需要两类主动轴时记为 powered-mixed。振动等其他动作记为 other。固定结构和完全由人操作的按钮或旋钮可标为 stationary，手动位移用 interaction.controls 表达。按选型阶段保存的 motionRequirements 核对轴数和最长旋转父子链层数。各自独立的转轴可以有多个根；串联关节要通过 parentIndex 连接，并让上游带动下游。

装配中的初始位置一律取收回状态。对装置驱动、需要预览的直线运动，填写 cadPlan.motions；其余写空数组。每组运动包含 type=prismatic、动作的中文 name、axis（装配世界坐标下指向伸出端的单位向量）、travelMm（从完全收回到设计伸出端的正毫米数）。选择可实现该行程的驱动方案。movingBodyIndices 是 bodies 数组中所有随动几何的零起始索引，包括活动接触面、滑座、推杆以及随动传感器。它不是 BOM 索引。保留基座、固定驱动壳体和固定导向在原位。同一 body 只参与一组运动。

区分零件的朝向与行程的方向。装配坐标的 +Z 是重力反方向。明确要求“垂直向上伸出、向下收回”时，手或接触面的伸出端比收回端高 travelMm，两端的 X、Y 坐标相同，axis 为 [0,0,1]。只说“垂直伸缩”时，轴线与 Z 平行，伸出端在上还是在下由安装和交互确定。沿桌面水平伸出时，两端 Z 相同。回程沿同一条路径逆向运动。若用户把旧方案的水平动作改为竖直动作，同时调整执行器、导向、固定座、开口与随动件的初始安装位置，复算两个端点的净空；旧版简介和轴向都是修订前的记录。按用户明确指出的那组动作处理，多自由度机构逐组分辨。只指定“碰拳”或只要求拳面朝上时，行程方向仍由交互情境决定。

当推杆穿过固定导套时，先确认杆与导孔同轴、横向位置和孔径允许滑动，再计算搭接长度。用 dot(世界坐标点, axis) 将固定导套有效内孔段投影为 [g0,g1]，把收回位置推杆上能导向的直段投影为 [r0,r1]，均按从小到大排列。行程 s 处的轴向搭接为 max(0, min(g1,r1+s) − max(g0,r0+s))。分别代入 s=0 和 s=travelMm，两者都须达到所选器件要求的最小搭接。若任一端不足，调整杆长、导套位置或行程再算；同时沿执行器输出端、推杆接头和随动件检查传力连接在两端均连续。步骤中记录两端的设计搭接值和依据。没有额定搭接资料时，将阈值标为待实测的设计假设。

actuatorPartIndex、guidePartIndex、controllerPartIndex 都是 BOM 索引，这三种职能都须有已定位的 body。一个购买件确实集成多种职能时，对应字段可引用同一行。让固定体、随动体、手可接触的表面在选型和空间上对应起来，给伸出端留出通路、给移动线束留弯曲余量。步骤写出如何检查两端位置、遮挡/干涉、限位和轻触反馈。只声明计划中实际表达的运动；仅通过视觉预览，不能宣称已验证载荷、公差、人体接触或实物能动。
