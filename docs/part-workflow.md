# 逐件处理与持续设计任务

正常网页在本机后台支持 `designJobs` 时，使用持久任务完成设计。讨论需求后，后台先规划 BOM，再查询每一项的商品和机械资料，下载可用的 CAD，生成装配，执行几何与交互检查，再由独立模型评审。未通过时将草稿、资料和具体问题一起送入下一轮。

对轻量 demo，生成与评审 skill 优先选择能完整展示核心交互的简单方案，不默认添加停车架、收纳设施、手势库或复杂授权流程。修复规划将首轮 AI 推导的要求与用户最新反馈核对，返回更新后的 `requirements` 和原因；后台保存 `requirementRevisions`，后续生成与覆盖检查使用新要求。用户明确要求的能力不因修复困难而降低，AI 自行增加的假设不永久锁定成验收条件。

## 各阶段共用的设计规则

`server/skills/hardware-design-policy/SKILL.md` 是共同规则的单一来源。`modeling-guide.mjs` 按阶段读取共同约束及相关章节：选型、逐件查证、独立模型、整机装配、功能评审、增量修复。规则文本随实际请求发送，版本随选型 generation、researchProvenance、reconstruction、设计 skill、评审 skill 或修复计划的 policy 保存。本地与 Worker ASSETS 使用相同文件，构建会打包它。

先联网查现成产品、成套机构与成熟模块，允许直接复用能满足需求的总成。只有用户明确要求原创的部分，或已有产品确有不适配的功能/接口，才进一步自定义。选型阶段的实际来源保存在 `generation.sourceUrls`，理由写入方案摘要；逐件查证仍单独确认完整型号及其资料。

采购件按实际形状表达，保留识别、安装和接口特征；无原厂 CAD 时按资料重建的是这个商品的模型，并不改变其采购身份。用于安装的 reference box 必须在最终展示中被真实几何替换。外置成品电源默认保持外置，先选匹配规格，不为它生成额外收纳和安装设施；现成产品已有外壳、驱动和附带件不重复设计。

这些改动是提示分发与版本追踪，不代表所有语义要求已变成确定性校验器。复杂曲面/贴图的原生 ForgeCAD 接入、实际图片输入、专门外形核对、稳定缺陷编号及收敛控制仍须分别实现。相关证据和问题清单见 `docs/validation/2026-11-24-general-hardware-findings.md`。

## 任务与版本

- `POST /api/design-jobs` 创建任务；`GET /api/design-jobs/:id` 返回实际阶段及结果。关闭网页不会取消任务，重新打开可以恢复轮询。
- 后台在 `~/.formbench/design-jobs/:id/` 保存目标、资料记录、当前生成结果、每轮草稿与评审、已编译几何。服务重启后，读取未结束任务会继续处理已保存的进度；已有本轮草稿时，优先处理其最新 BOM，保留已完成的来源和模型。
- 每个后台执行时段处理三个设计回合，最长三小时；总装配 API 步骤最长一小时，其他结构化步骤最长三十分钟，逐件联网研究最长十五分钟。长时限用于容纳最高推理档，避免用完推理时间却反复丢弃结果；收到结果后立即进入下一步。时段结束后保存进度。逐项检查仍有进展时继续增量修复；同一问题持续两轮没有经验证的改善时重新规划，重规划后仍停滞或只剩已确认的平台缺口时暂停自动续修。检查结果未通过的草稿不会作为正常成品发布。
- `POST /api/design-jobs/:id/cancel` 取消；`POST /api/design-jobs/:id/retry` 恢复已停止任务。短暂服务错误自动恢复最多三次；连续服务失败保留进度。取消会同时阻止排队的下一执行时段。
- API 明确返回额度耗尽时，优先按 `OPENAI_API_KEY`、`OPENAI_API_KEY_2`、`OPENAI_API_KEY_3` 等顺序切换到下一把不同密钥，使用同一模型、推理档位和请求内容重试当前步骤。生成中的 SSE 额度错误也进入切换；未完成输出不当作结果。普通限流、网络、鉴权或模型权限错误不会被标为额度耗尽。
- 全部配置密钥均额度不可用时，才停止启动新的付费查询和建模，保存已返回的资料、草稿和模型；已在途的逐件请求结束后保存其结果。任务返回 402，不按普通 429 限流自动重试。本机运行期间跳过已耗尽的密钥；服务重启重建密钥状态，但仍识别任务已保存的额度错误。补充额度或添加备用密钥后，通过原任务的继续操作恢复，清除额度错误、相关查询计数和运行时耗尽标记，不重置设计轮次或已完成模型。
- `design-review.html?job=:id` 显示逐轮结果和最后的结构。未通过的版本明确标为草稿；无效的交互定义不会被当作已运行的行为。`?job=:id` 可打开已完成的正常项目。

目前持久任务与动态模型资产由本机 Node 服务提供。静态 GitHub Pages 和现有 Cloudflare Worker 没有接入这套持久存储，不能据此宣称云端生成流程已上线。

## 每件零件的处理

1. 购买品、材料、定制件、随主件附带的附件，以及用户已有设备分别记录。附带件与已有设备默认不列入本次采购。需要独立安装的附带件仍查询自身机械资料和 CAD，保持随附身份，不要求单独购买链接；拆出内件时不能沿用整套模型冒充它的几何。
2. 查询使用 OpenAI API 的网页搜索工具。商品页、型号资料和 CAD 链接必须出现在实际查询来源中；模型自行写出的陌生 URL 不会被保留为来源。
3. 公开的直接 STEP/STP/STL、单个模型的 CAD ZIP、原厂 GitHub 文件或目录、包含实际文件链接的下载页可自动处理。同一件同时提供 STEP 和 STL 时优先 STEP；不同零件的压缩包不能自动视为整件。需登录、受限的动态 CAD 门户、无法下载的文件或内容不匹配的链接会记录失败原因。
4. 文件在后台真正下载后，由已有 STEP/STL 读取器解析，保留原生毫米尺寸、原始文件和网格，存于 `~/.formbench/models/:id/`。只有这一步成功才标为已导入。实际网格的子件名称、数量和包络也交给装配阶段，所有子件边界与原 CAD 原点都换算到同一个居中坐标系，以便识别已经包含的附件；边界不能代替精确孔位。
5. 已导入模型按原生尺寸、实例数量和安装朝向注册到装配，查看器与 ForgeCAD 工程使用同一来源。资料不足或下载失败的安装件依据已取得的尺寸和接口信息独立建模，并用 ForgeCAD 编译后保存模型配方、基准及估算，再放入整机；已匹配的目录模型继续复用。重建件的安装基准使用结构化点/方向，与实际几何同步居中，防止单独平移模型后留下旧坐标。
6. 未变型号复用来源；厂名公司后缀的写法变化不视为换型，型号、封装或版本变化则重新处理。CAD 传输失败单独重试下载，避免重复整轮搜索。修复阶段可指定具体问题重新查该件；找到新 CAD 地址后重新尝试导入。

逐件研究使用结构化 `part_research`，明确每组来源对应的完整型号。当前商品与替代候选分开保存；不同型号的 URL、尺寸和 CAD 不合并到当前行。AI 选择替代候选时须明确修改 BOM，随后按新身份研究和建模。旧版定向查询缺少对应型号字段时自动复核；型号和原来源重新确认一致的模型继续复用，否则移出当前证据，避免混用。未确认身份会阻止该记录建模和最终完成。

查询回复被输出预算截断时，保存未完成文字并把该件下次查询预算从 16,384 提升至 32,768，必要时至 65,536。未完整的回复只作为续查上下文，不作为装配事实或部件型号已确认的证据。

装配后新增的型号会再次研究和建模。接受草稿前检查购买/随附整件的 BOM 尺寸及每个安装实例是否真正绑定新模型；仍使用旧的估计形体时，将具体尺寸、数量和基准问题交给 AI 修订。执行器拆成固定/运动子件及原料裁切件按其对应表达处理。

实际研究完后，后台自动执行至多两次局部装配对齐：比较原厂或独立重建模型与 BOM 尺寸、完整锚点及数量，调用同一增量修订 API，重查受影响部件，再进入完整编译与评审。每次 `alignments` 操作和模型用量都存入当前草稿及轮次；重启复用已完成的对齐，未解决的差异继续作为缺陷进入下一轮。明确画在主体外的成品电源等同样可以按所选商品重建；不为它自动新增托盘或收纳结构。

单件建模若用完 32,768 token 预算仍未返回完整结果，会保留失败原因并将该件后续预算提升到 65,536、请求时限提升到一小时，推理仍使用 `max`。预算提升随该件保存。被截断的输出或被几何检查拒绝的完整草稿也保存，重试同时收到该草稿与具体错误；它们不会作为已通过的模型，也不会堆入整机调用的零件资料。

成功编译的模型以 `evidenceVersion` 记录当次资料的 `queriedAt` 与定向修订问题。恢复时先完成的单件若已使用同一版资料解决相同问题，后续修复计划不再重复排入建模；新资料或新问题仍会触发修订。旧模型没有该记录时不补造版本或通过状态。

整机输出截断时同样保留未完成正文、失败原因与用量，将 65,536 的预算提升至 131,072 后自动恢复。BOM 最多 132 行，继续编辑与采购交接采用同一上限，不能靠丢弃部件使大设计进入页面。定向补查需要重建单件时，保存上一版已编译模型作为修订输入；新版本仍须重新编译，不直接沿用旧版的通过状态。

完整装配评审和修复规划的初始预算均为 65,536。遇到输出额度截断时，这两个阶段在当前调用内携带原始证据和未完成文字，将预算提高一倍（最多 131,072）再尝试一次，不重新执行已成功的 CAD 编译。完整结果记录恢复前后额度、截断字符数与用量；再次截断仍为失败，不能发布半份结论。单件和整机几何沿用各自持久化的草稿恢复路径。

商品页已读取、搜索结果支持、原厂 CAD 已导入、按资料建模是不同状态。真实商品页也不等于已确认淘宝 SKU、实时库存或可直接下单的配置。

## 检查与交互

每轮执行结构数据校验、实例/外壳覆盖检查、ForgeCAD 编译、离散姿态的实体相交检查、可表达的交互事件回放，以及独立的意图/形态/机构/控制评审。实际 CAD 的外观、正面、侧面、顶面和内部图像进入评审，并加载已导入及已匹配的目录网格。评审问题先交给 AI 制定修复计划，再进行定向补查或结构修改；连续失败时重新规划失败子系统。用户不需要审核工程决策。

交互结构字段有效后，机械绑定、电气连通、端子位置和状态逻辑分别检查并汇总问题。一项失败不会隐藏其他类别的失败；恢复旧任务时修复规划会重新取得当前校验结果。通过标准不因错误数量多而改变。

AI 也不能将必要电路、接口隔离或传动设计改写成“制作方现场查明并补齐”。制作方依据设计加工、装配和测试，尚缺的工程方案由 AI 补查与修订。实物公差和性能验证仍单独记录。

`cadPlan.joints` 支持串联旋转关节：父关节携带子关节的定件和动件，网页提供逐轴操作，整机 STL 导出保持当前关节姿态，ForgeCAD 源文件导出原生装配关节。单轴离散采样没有覆盖整个多轴组合空间，编译与动画也不验证实际扭矩、制造公差、布线导通或固件。

内部视图中的参考接线端点也随各自实体的串联关节运动。同一运动组内的参考线整体跟随，不同组之间的线形仅用于说明连接关系；这不是恒长线束、柔性变形或布线空间的验证。

共享 USB 数据线的不同触控事件使用各自的事件标识，不能为每个按钮虚构独立 GPIO。用户已有手机可以作为接口和尺寸参考，实际机型、主从角色、数据协议及电机独立供电仍需明确。

网页或手机 Agent 的指令使用 `controls.kind=command`，保留外部主机及真实通信路径，`fixedBodyIndex=null`，不要求手机/按钮 CAD。模型下方的交互控制台直接显示这些命令；关节区提供滑杆、±5°点动、停止当前持续按压及回到初始姿态。它们调用同一 CAD 运动状态，尚不代表实机急停、回零轨迹或手机固件已经实现；当前未加入笛卡尔逆运动学与手势库。

`interaction.systemEvents` 分别表达连接变化、超时、故障和反馈，记录检测器件、真实接线针脚、触发条件，以及超时事件的毫秒阈值。它们没有活动 CAD 实体，不冒充用户按钮。现有 XState 状态机用显式事件注入回放，网页折叠显示“模拟连接与故障”，只在当前状态有对应转移时可触发。回放记录明确这是逻辑事件注入；它不模拟 USB 报文、固件时钟或制动过程，也不验证实际延迟达标。

交互支持 32 个用户控件、16 个输出、64 个状态、24 个系统事件及 512 条转换。旋转增量可带符号，几何采样保持相同密度；直线行程仍必须为正。触屏没有活动实体，通用 step 字段不参与运动。运动输出可以绑定 CAD 明确由执行器驱动的负载；同一型号多实例时，还核对信号端子对应的实例与关节定件。具名端子映射到不同实体、且 BOM 数量大于 1，才能把同一 BOM 行内部的连接识别为实例之间的外部线；单器件内部通道仍需资料。

有挡位的旋转控件使用 range 的 min/max/initial 及 `.increase`/`.decrease` 接点事件；越过已到达的挡位无效。持续按压使用同一控件的 `.down`/`.up`/`.cancel`；网页按住、抬起、取消及键盘操作驱动这些事件。运动输出的 motion.type/index/speed 绑定既有 CAD 关节或直线行程，状态的 forward/reverse 区分轴向，并通过原有关节变换更新实体；到行程边界停止预览。该运动预览不模拟载荷、扭矩、固件或制动时间。

装配容量为 320 个实体、每体 80 个特征、展开独立模型后总计 4,096 个特征，BOM 为 132 行。校验器、查看器和安装位置共用实体上限，安装件不能以合并实例绕过数量检查。服务端相交检查为每一轴及每个联动姿态单独分配最多 30,000 次窄相检测额度，整次检查时限为十分钟，并使用查看器的串联变换采样同向/交错端点及中间组合；报告明确这是离散检查，未穷举全部关节空间。

所有已有设计的修订均使用 `hardware_design_revision`，不设尺寸阈值：自动修复、用户修改需求，以及从未通过的草稿继续，都以保留的版本为基线。AI 返回 `add/replace/remove` 的 JSON Pointer 操作及 JSON 字符串值；服务器仅对上一轮草稿的副本应用操作，不执行生成的程序。后台拒绝整体写入或删除 `/parts`、`/cadPlan`、`/cadPlan/bodies`，防止用一个大替换冒充增量；操作必须落到具体项或字段。操作无效时将具体错误交回模型修正，原草稿不变。后台复用未变部件的资料与独立模型，新增或变更部件继续查证、建模；应用后的完整候选仍经过 CAD 编译和独立评审，保存每轮操作及完整结果。没有因此免除几何、电气或功能检查，修改失败也不自动退回全量生成。仅没有旧设计的首轮输出完整设计；更新前已截断的旧格式请求仍按其保存的格式恢复。请求只附一份当前修订基线，不在对话上下文中重复整份旧设计。增量主要减少重复输出与无关改动；整机上下文和完整评审仍消耗 token，不保证固定比例的费用下降。

发送 `selectedParts/updatedParts` 时，同型号且已有服务器来源快照的条目只携带当前 `research`，省去从它生成的 `hardwareReference`、`geometryReference`、`sourcing` 和 `importedModel` 展示副本。BOM 字段、当前来源链接、机械事实、重建基准和原厂模型组成仍保留；不修改持久化数据，没有对应来源快照的用户参考也保留。完整几何和评审依据不因此裁剪。

用户要求在某轮完成后先看结果时，任务目录的 `control.json` 可设置 `pauseAfterAttempt`。该轮完整评审保存后，若仍需修订则进入 `paused`，网页轮询和服务重启不会自动启动下一轮；显式继续才清除暂停条件。暂停不发布未通过的 CAD，保留轮次、操作、完整草稿及检查记录。若该轮通过，则正常完成。

明确的 USB 数据对跨器件连接按双向导线检查，内部数据开关仍需有型号及输入/输出针脚证据的通道声明；VBUS 不充当数据信号。直接切换电源的机械开关使用真实电源触点与活动实体，无需虚构主控输入。外部用户自备 USB Host 以其 VBUS 输出、共地及数据链表达角色，不要求另画手机内部电池。

运行时会读取 `server/skills/interaction-hardware/SKILL.md` 和 `server/skills/functional-review/SKILL.md`，并按阶段加载固定版本的 ForgeCAD 官方 skill。用途、实际接入状态和版本限制见 `docs/forgecad-official-skills.md`。它们是 API 工作流的输入。调用显式要求最大推理 `max`，真实 API 支持情况已用当前模型核验。

## 验证入口

电气表达最多支持 160 条连接、320 个端子和 24 条有来源的内部信号通道；每条连接保留类型、器件索引和针名检查。容量允许两端各自独立定位，不把超出旧的 96 条限制误报成电气设计错误。

ForgeCAD 实际编译的原始 STL 总量上限为 96 MiB，单件最多 65,000 个三角面；base64 结果采用 144 MiB 流式响应上限。查看器等待时间随实体数量增加。失败说明定位到具体 body 和 BOM 索引，并区分空实体、单件复杂度和整机文件总量，避免错误地要求 AI 修改一个有效部件。
