# ForgeCAD 官方 skill 与运行阶段

本项目保留了 ForgeCAD public kit 的 10 个官方 skill 原文件及所需文档、脚本。来源固定到公开修订 `7523f68ce05ec642608c7f2001c5ae7ca7b1bee0`，提取日期 2026-11-22。它是可核对的公开版本，不表示当前主分支的最新版本。原文、许可证和来源清单保存在 `server/skills/forgecad-official/`；本项目规则通过单独的 `server/official-skills.mjs` 适配，不改写原文。

| 官方 skill | 原本负责什么 | 本项目的阶段和实际接入方式 |
| --- | --- | --- |
| `forgecad-design-spec` | 将意图转成设计要求、架构与详细规格；用默认方案补全信息，维护设计迭代 | 规划加载 Intake；取得逐件资料后，装配调用加载 LLD；失败后的修复计划加载架构决策部分。AI 自己决定工程细节，不保留原工作流中需要用户审阅 HLD/LLD 的环节。 |
| `forgecad` | 核心建模入口、文档选择、装配、坐标、CLI 等 API 的使用规则 | 设计调用一直加载版本固定的主指导；按阶段追加其他原文。实际内核是 ForgeCAD CLI 0.8.2，声明式 CAD 经适配器转成 `.forge.js` 执行。 |
| `forgecad-build-model` | 拆小部件逐层建模，先运动骨架后实体，做真实闭合产品；反复渲染检查 | 整机生成和修订，原文加载；同时加载 `joint-design.md` 与 `positioning.md`。采购件先单独建模编译，再装入整机。 |
| `forgecad-reconstruct-from-images` | 从参考图片重建，确定尺度与观察方向，对照渲染查差异；区分事实与估算 | 无 CAD 的采购件重建。已接入证据、尺寸、基准和估算分开的方法；目前后台自动获取的是网页文字/尺寸，未自动获取商品照片，因此没有声称执行其完整图像对齐流程。 |
| `forgecad-reconstruct-cad-file` | 将已有 CAD 重建成可编辑的参数模型，并对比原件与重建结果 | 原文件保留；正常采购件直接导入 STEP/STL，不默认重建。以后确需参数化修改已有 CAD 时才触发。当前没有自动调用。 |
| `forgecad-inspect-model` | 选择检查视角、剖切和检查对象，阅读实际检查输出；避免把编译成功当作装配成功 | 每轮编译后的检查及修复规划。运行现有几何检查，渲染外观、正/侧/顶面和内部五图，再送入评审；不宣称调用了运行时没有的新版 `inspect` 命令。 |
| `forgecad-grade-model` | 按要求、几何与实际证据独立评分/评审，发现缺件和不合理结构 | 每轮独立评审，加载原文并按本项目结构化评审格式返回。缺陷回流到修复计划，不能仅凭美观通过。 |
| `forgecad-verify-mujoco` | 用 MuJoCo 检查关节、碰撞、动力学及模型导入/执行结果 | 原文与脚本保留。尚未接通 MJCF → MuJoCo 执行；当前关节运动/几何采样不能当成这项验证。 |
| `forgecad-image-prompt` | 基于已完成 CAD 生成产品展示图的提示 | 可在设计完成后的产品展示环节使用。目前不参与工程检查，也没有用图像生成代替模型。 |
| `forgecad-project-sync` | 把本地项目与 ForgeCAD 托管项目同步 | 可用于交付或托管协作。当前网站不依赖该托管服务，没有自动调用。 |

## 实际的自动循环

1. 需求规划：保存用户要求和验收条件，AI 先联网查成熟机构与关键驱动/控制接口，再确定架构和初始 BOM。本阶段只加载 Intake；详细尺寸和 CAD 在逐件研究后处理。规划来源与逐件型号查证分别保存。
2. 逐件研究：寻找实际商品页、型号资料和可读 CAD；保留已读来源、下载结果与失败原因。
3. 独立零件：保留原厂/供应商模型；无可用文件时按资料建模并实际编译。已匹配的目录模型继续复用。
4. 装配：按基准布置所有实际实例、自制外壳、控制板、电机、安装/传动件及运动关系。
5. 检查：结构数据校验、覆盖数量检查、几何和交互检查、实际 ForgeCAD 编译及多视角评审。
6. 修复：AI 制定具体修复计划。缺资料就定向补查；下载失败就换来源或重建；连续缺陷就改失败子结构。重新生成后重复检查。
7. 完成：只有检查没有待修设计问题才发布结果。有可执行的修复并持续取得进展时可以跨时段续跑。重规划后仍停滞、只剩已确认的平台能力缺口、执行失败或收到用户停止指令时，保存草稿及证据。

托管 MCP 使用另一个连接入口，按实际会话发现工具和参数。后台授权、调用范围与本地 CLI 的分工见[本地 ForgeCAD 接入](local-forge.md)。

## 推理和证据

规划、研究、独立建模、装配、修复和评审请求显式设置 `reasoning.effort = max`，由当前配置的 OpenAI API 模型执行。硬件总设计的初始输出/推理预算为 65,536 tokens；长度截断后保存未完成正文并提高至 131,072。完整装配评审和修复计划的初始预算均为 65,536，截断后保留原证据与不完整正文，再提高预算尝试一次；不接受未完成的结论。其他结构化步骤为 32,768，逐件网页研究为 16,384；单件重建截断会升至 65,536。2026-11-22 的真实 API 探针返回 `gpt-6.2-astra`、`effort: max`、`mode: standard`，并确认更高额度参数可用。没有把参数可用或“设置了 max”解释为复杂设计自动成功。

任务记录保留每轮候选、失败项、修复决策、查证记录、单件重建说明、实际编译结果、评审图像及返回的模型/推理设置。软件设计检查通过不代表已完成制造、通电、载荷或人体接触试验。
